## 📖 项目简介
**Frame Keep** 是一款基于 HarmonyOS 原生能力打造的全链路视频编辑与媒体管理应用，采用 ArkUI 声明式框架开发，深度整合系统多媒体处理能力，为用户提供从素材管理、内容创作到灵感交流的一站式移动端创作体验。

- **核心价值**：打破媒体管理、剪辑创作与灵感获取的场景壁垒，在鸿蒙设备上实现轻量化、高效率的内容生产闭环。
- **核心亮点**：
  - **原生性能体验**：全量 ArkTS 开发，深度适配鸿蒙渲染引擎，交互响应流畅无卡顿
  - **全链路创作闭环**：覆盖相册管理、视频剪辑、字幕编辑、作品导出的完整创作流程
  - **工具+社区双生态**：内置海量模板与场景灵感库，兼顾生产效率与创作创意

## ✨ 核心功能

### 3.1 媒体资产与相册管理 `/pages/album` `/pages/collect`
- **全量媒体浏览**：对接系统媒体库，高效加载并展示设备内所有图片与视频资源
- **自定义相册分组**：支持创建专属相册，实现媒体资源的逻辑分类与批量管理
- **素材收藏体系**：支持外部素材导入，通过标签体系实现精细化归类，配套回收站保障数据安全

### 3.2 专业视频编辑引擎 `/pages/video`
- **精准轨道剪辑**：可视化时间轴视图，支持视频片段裁剪、拼接、时长微调
- **多轨字幕编辑**：支持多语言字幕添加、位置调整、样式自定义，增强视频表现力
- **音频混音控制**：独立调节视频原声、背景音乐音量，实现专业混音效果
- **多规格导出**：支持多清晰度、多格式选择，高效渲染导出最终作品

### 3.3 模板与卡片创作 `/pages/card` `/pages/create`
- **精品模板库**：覆盖多场景的精美排版模板，一键套用，快速生成创意内容
- **可视化编辑器**：支持素材替换、文字编辑、样式调整，低成本实现个性化创作
- **个人模板沉淀**：支持保存自定义模板方案，实现创作资产复用

### 3.4 探索与灵感社区 `/pages/discover`
- **精选内容首页**：每日更新优质作品、创作教程，传递前沿创作思路
- **场景分类库**：按风格、主题分类的场景集合，帮助用户快速匹配创作基调
- **热门话题片单**：聚合热点话题与系列内容，引导社区创作互动

### 3.5 用户与系统中心 `/pages/profile` `/pages/auth`
- **账号认证体系**：完整的登录、注册流程，保障用户数据安全
- **创作数据统计**：可视化展示作品数量、媒体资产规模等个人创作数据
- **系统偏好设置**：支持个性化配置、帮助反馈与系统功能入口

## 📂 项目结构
项目遵循标准 HarmonyOS 工程规范，按业务域模块化拆分：

```text
Frame Keep/
├── AppScope/                 # 应用全局配置层
│   ├── app.json5             # 应用全局配置文件
│   └── resources/            # 应用级全局资源（字符串、主题色等）
├── entry/                    # 主业务模块
│   ├── src/main/ets/         # ArkTS 核心业务代码
│   │   ├── common/           # 公共能力层
│   │   │   ├── components/   # 可复用自定义组件
│   │   │   ├── utils/        # 工具函数库
│   │   │   ├── store/        # 全局状态管理
│   │   │   └── constants/    # 常量与配置定义
│   │   ├── entryability/     # 应用入口与生命周期管理
│   │   └── pages/            # 业务页面层（按功能域划分）
│   │       ├── album/        # 相册浏览与管理
│   │       ├── auth/         # 登录注册鉴权
│   │       ├── card/         # 卡片模板编辑
│   │       ├── collect/      # 素材收藏管理
│   │       ├── create/       # 创作中心
│   │       ├── discover/     # 发现与灵感社区
│   │       ├── profile/      # 个人中心
│   │       └── video/        # 视频剪辑工作台
│   ├── src/main/resources/   # 模块级本地资源（图片、多语言、rawfile 等）
│   ├── src/mock/             # 本地开发 Mock 数据
│   ├── src/test/             # 单元测试代码
│   └── src/ohosTest/         # UI 自动化与集成测试
├── build-profile.json5       # 项目构建配置
├── hvigorfile.ts             # Hvigor 构建脚本
└── oh-package.json5          # 项目依赖声明
```

## 🚀 环境与运行

### 环境要求
- **开发工具**：DevEco Studio 3.1 及以上版本
- **系统 SDK**：HarmonyOS SDK API Version 9 及以上
- **运行设备**：HarmonyOS 3.1 及以上版本真机 / 官方模拟器

### 运行步骤
1. **获取代码**：将项目代码克隆或下载至本地
2. **导入工程**：打开 DevEco Studio，选择 `Open Project`，选中项目根目录导入
3. **同步依赖**：等待 IDE 自动执行 Hvigor 同步，完成 `oh-package.json5` 依赖解析与下载
4. **配置签名（真机必选）**：如需安装到真机，在 `File > Project Structure > Modules > Signing Configs` 中配置开发者证书
5. **编译运行**：点击顶部工具栏 `Run` 按钮，选择本地模拟器或已连接的真机，完成编译安装

## 🧪 Mock 数据说明
项目内置完整 Mock 数据体系，无需对接后端即可快速预览全量交互效果：
- Mock 数据文件路径：`entry/src/main/ets/common/MockData.ets`
- 覆盖场景：相册列表、模板库、发现页内容、用户数据等核心业务场景
- 本地资源：测试图片、指导文档等静态资源存放于 `entry/src/main/resources/rawfile/` 目录
- 替换方式：二次开发时，可直接替换 Mock 数据源为真实后端接口，无需改动页面业务逻辑
